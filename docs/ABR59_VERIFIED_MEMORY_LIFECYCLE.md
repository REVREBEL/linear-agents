# ABR-59 M13 — Verified Bridge memory lifecycle

## State and scope

This PR is **source-only** and inert by default. M11 proved live provider identities and authority credentials; M12 proved native scoped PostgreSQL roles and signed source persistence in a disposable database. M13 connects them in source and exercises the same end-to-end control flow in a fresh disposable cluster. M14 still owns installing the dedicated root runtime, provisioning PostgreSQL scoped logins/HBA mapping, completing the service/IPC privilege boundary, an independent approved production activation, and verifying a live positive/negative canary. No application service, production PostgreSQL schema or root credential file is changed by this PR.

The Bridge service is a non-root `bridge` process whose agent subprocesses may share the same Unix identity. Merely installing a Unix socket accessible to that Unix account **would not** authenticate individual agents or confine cross-job memory access. M14 must use a separately reviewed OS-level job/service distinction or equivalent verified host-specific admission capability; no general-purpose root socket or password/credential is shipped here. The reviewed root-controlled client file is not a bypass around that requirement.

## Operator-side promotion

`memory/verified-memory-lifecycle.mjs` captures an operator-pinned exact `jobId`, `{tenantId,agentId,repositoryId,issueId}`, PR number, 40-hex head SHA, independent CI app/check and reviewer policy, root-only authority directory, trusted Git checkout, and exact `docs/verified-learnings/*.md|*.txt` source path. Only the operator-controlled configuration supplies these values. Call `promote({issueId,jobId})` after a completion notification **as a hint**; the notification cannot supply GitHub/Linear facts, a candidate text, PR/SHA, repository path, a policy or credentials.

The coordinator reads raw committed Git object bytes with bounded arguments, rejects malformed/oversized/instruction-like text, independently re-verifies the tracked blob through the M7 Git verifier and builds a 7-day, revision-1 learning source. It initializes real M11 restricted read-only provider clients and the M12 scope-bound native PostgreSQL writer. `stage()` independently checks current merged PR head, distinct authorized reviewer, required trusted checks and unchanged exact SHA. A fresh Linear read must confirm completed status and matching repository/SHA **even on replay**. `commit()` checks immutable journal receipt and current external facts again, claims an irreversible commit-start marker and calls native memU once; `approve()` checks independently confirmed durable markers before writing an operator-signed source. Repeated identical fully confirmed approvals may return `already-confirmed` after fresh review/Linear verification. An uncertain/partial commit is **never automatically repeated**; reconcile its exact native file and segment through root-only operator procedures.

For recall, the operator reloads only a signed, unexpired, confirmed approval for that pinned job and asks its M12 dedicated **reader** for the exact receipt ID and native scope. The read adapter checks the segment, embedding dimensions, exact content/description and independently signed digest before yielding a bounded `untrusted-reference-only` envelope. Separate process calls reload the immutable state; a revoked/rotated signing key, expired record, missing marker or foreign scope denies read.

## Live Bridge opt-in

The canonical `bridge/server/agent-bridge-runtime.mjs` selects verified memory only on `BRIDGE_VERIFIED_MEMORY_ENABLED=true`. Default off does not load or call any host binding. When enabled, `bridge/orchestration/verified-memory-bridge.mjs` loads exactly `/etc/agent-bridge/verified-memory-host.mjs`, requiring a root-owned regular file and root-owned, non-group-writable/non-other-writable real parent directories. An absent or unsafe binding stops startup. This is a **client only**, not a place to store PEM, OAuth, HMAC keys, database DSNs or root authority functions.

That protected client must export `createVerifiedMemoryBridgeHost()`, returning two asynchronous functions:

- `getApprovedScopedRecall({tenantId,agentId,repositoryRoot,issueId,jobKey})`: independently resolve admitted job/scope and canonical GitHub repo via the operator-approved host mapping, check the signed source and return an exact `{schemaVersion:1,trust:"untrusted-reference-only",scope:{tenantId,agentId,repositoryId,issueId},entries:[{content,sourcePath,sourceGitSha,revision,expiresAt,digest}],text}` response or null. Only one job may own the requested receipt; never trust a supplied scope as identity. Bridge rechecks tuple, hash, expiry, size, secrets, directives and result count before formatting.
- `notifyIssueCompleted({issueId})`: send an advisory signal to the separately authorized operator coordinator. It is **not** permission to commit. The operator resolves its pinned job independently and rechecks GitHub review/CI and Linear completion; do not trust the Worker/webhook claim or local job file to select a PR/source. A duplicate signal must not duplicate a write.

Each call is bounded to 1.5 seconds at the Bridge boundary, with redacted success/denial/timeout/unavailable indicators. A failed recall omits the reference instead of failing admission, and an unavailable completion notifier does not fail the existing cleanup. The task prompt includes at most five notes labeled **SCOPED VERIFIED MEMORY — LOWER-TRUST REFERENCE ONLY** and a warning that they are data, never instructions/approvals, positioned before the actual task. Legacy optional memU CLI results continue to be withheld. No public endpoints, new webhook handlers or automatic synchronization loops are introduced.

The host-side service implementation, root runtime hardening, per-job authorization and production deployment are separate reviewed M14 gates. Merely enabling the environment flag without installing a compliant protected host client must fail closed.

## Validation and recovery

Unit and integration suites cover exact pinned authority, finished task hints, verified Git bytes, current GitHub checks/review and Linear completion, manual reconciliation after uncertain native commit, signature/read restart, foreign scope, key revocation, malicious/expired references, default-off behavior, bound timeouts, real task file preparation and authenticated issue completion. The existing `bash memory/scripts/verify-memu-restricted-db.sh` extends the native Percona PostgreSQL 18 disposable acceptance: five scopes and ten limited logins, server restart, a new M13 pinned PR and signed commit/approval, a **different Node process** performing real scoped PostgreSQL recall, denied CI-review/reopened issue replay, cross-scope refusal, data-preserving logical backup/restore and disabled-login rollback. GitHub/Linear evidence in this disposable test is synthetic; no live credential call is made.

A failed promotion produces only redacted `denied` or `reconcile` statuses; never print payload text, tokens or SQL errors. If a confirmed marker is missing or native bytes differ, keep writes disabled and use the M12 manual reconciliation plan. Disabling the Bridge opt-in flag stops new references and hints; revoke the operator key and M12 scoped DB logins for a complete shutdown, retaining journal/data until an approved reconciliation.
