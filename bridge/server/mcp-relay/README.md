# Local-only MCP relay foundation (ABR-94)

`index.mjs` independently implements a **test-only** local Streamable-HTTP-like JSON-RPC subset plus an outbound WebSocket paired-agent channel. It binds solely to 127.0.0.1 with an ephemeral port and accepts only explicit 127.0.0.1 Host/Origin identities; no production server, OAuth, Cloudflare listener, profile deployment, or agent execution is activated.

`createLocalMcpRelay({ clientToken, agentToken, deviceId, profile })` accepts separate >=32-character test secrets and a fixed approved device identity. Only `list_devices` and bounded `read_file` are executable. All other tool names, device IDs, websocket credentials, origin/header spoofing and public capability-link paths are denied; profile names cannot elevate authority. HTTP body and pending-request lifetimes are limited; serialized host replies have a separate wire-byte cap and protocol errors close only the paired connection, never the listener. The protocol fixture is pinned to 2025-06-18 and **does not claim conformance to current external MCP clients**; full protocol/Auth/HTTP deployment belongs to ABR-95. The paired read-only host uses a Linux-only race-resistant dirfd file opener; macOS/Windows safe filesystem access must be independently implemented in ABR-96/97.

Consult [ABR-94 source audit](../../../docs/audits/mcp/README.md), the machine-readable [tool matrix](../../../docs/audits/mcp/tool-parity.json) and `scripts/test-mcp-foundation.mjs` before extending. **Never import the test listener from `agent-bridge-runtime.mjs` or run it as a system service.** ABR-95 owns remote ingress; ABR-99 owns authenticated Linear integration.

## OAuth resource-server boundary and dual-era request validation (ABR-95)

The optional `createLocalMcpRelay({ oauthResource })` path accepts a trusted, operator-configured `createResourceAuthorizer` from [oauth-resource.mjs](oauth-resource.mjs), which checks signed access tokens, exact issuer and resource audience (RFC 7519 single-audience JWT string or singleton array only), explicit registered client ID/user/device/tool grants, scopes, expiry, and revocation on every authenticated call. [protocol-compat.mjs](protocol-compat.mjs) recognizes modern MCP 2026-07-28 stateless `server/discover` and legacy 2025-11-25/2025-06-18 `initialize`, checking mirrored request headers and returning the spec-assigned `HeaderMismatch` / `UnsupportedProtocolVersion` errors. Only read-only ABR-94 tools are offered. A test-only PKCE issuer in `scripts/fixtures/` never enters the runtime.

The [ABR-95 security, Cloudflare, compatibility, and rollback plan](../../../docs/audits/mcp/OAUTH_EDGE.md) details configuration boundaries, the deliberately **local-only** status and remaining SDK/transport/client integration requirements; no process is automatically installed, exposed or started.

## ABR-98 — OAuth-only core/focused/full profile gateway

`tool-profiles.mjs` reconciles the 50-name [pinned inventory](../../../docs/audits/mcp/tool-parity.json) while advertising only **implemented, registered and granted** handlers. `core`, `focused`, `full` affect discovery only, not permission. The optional `toolProfileBinding` for `createLocalMcpRelay` requires the existing OAuth resource verifier and a separately injected trusted session-handle resolver; an exact-name call still needs OAuth tool scope and private session capabilities. The default ABR-94/95 two-tool relay and legacy shared bearer never expose expanded tools. Dangerous plugin/transfer and admin tools remain denied absent separately reviewed handlers/grants. A signed JWT is verified once per HTTP request; each advertised or invoked tool is independently checked using an opaque verifier-created proof tied to private scope/device grants, expiry and revocation. Forged proofs and mutation of public Set fields cannot elevate access; [ABR-98 runbook and measured schema benchmark](../../../docs/audits/mcp/PROFILES.md).
