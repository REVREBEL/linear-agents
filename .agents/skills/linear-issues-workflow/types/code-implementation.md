# Implementation and repair work orders

Use for features, fixes, refactors, CLI changes or adapters with repository modifications.

1. Inspect existing implementations, related tests, contracts and regression risk. Demonstrate why an edit is needed and choose the smallest compatible change.
2. Use a verified issue branch and approved workspace; preserve unrelated changes and protected areas. Add focused tests including negative cases for changed behavior.
3. Run targeted checks then applicable broader checks; document failures, test commands and any compatibility/migration implications.
4. **PASS** requires issue-specific behavior, tests, reviewable diff, no unauthorized side effects and verified change location.
5. Follow PR submission and review handoff. Do not deploy or publish merely because implementation tests pass.
